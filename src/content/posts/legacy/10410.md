详细的描述了MySQL中的触发器。

# 触发器简介

## 简介

触发器是与表有关的数据库对象，指在 insert / update / delete 之前或之后，触发并执行触发器中定义的SQL语句集合。触发器的这种特性可以协助应用在数据库端确保数据的完整性，日志记录，数据校验等操作。  
​

使用别名 OLD 和 NEW 来引用触发器中发生变化的记录内容，这与其他的数据库是相似的。

现在触发器还只支持行级触发（影响几行触发几次）

现在触发器不支持语句级触发（执行一条语句触发一次）

| 触发器类型 | NEW 和 OLD |
| --- | --- |
| INSERT触发器 | NEW表示将要或者已经新增的数据 |
| UPDATE型触发器 | OLD表示修改之前的数据，NEW表示将要或已经修改后的数据 |
| DELETE型触发器 | OLD表示将要或者已经删除的数据 |

## 语法

### 创建

```plaintext
CREATE TRIGGER trigger_name
BEFORE/AFTER INSERT/UPDATE/DELETE
ON tbl_name FOR EACH ROW --行级触发器
BEGIN
	trigger_stmt;
END;
```

### 查看

```plaintext
SHOW TRIGGERS;
```

### 删除

```plaintext
DROP TRIGGER [schema_name.]Jtrigger_name; --如果没有指定schema_name，默认为当前数据库。
```

### INSERT 类型触发器样例

样例：

通过触发器记录 tb\_user 表的数据变更日志，将变更日志插入到日志表user\_logs中，包含增加，修改，删除；、、

建表语句如下：

```plaintext
create table user_logs(
  id int(11) not null auto_increment,
  operation varchar(20) not null comment '操作类型, insert/update/delete',
  operate_time datetime not null comment '操作时间',
  operate_id int(11) not null comment '操作的ID',
  operate_params varchar(500) comment '操作参数',
  primary key(`id`)
)engine=innodb default charset=utf8;
```

```plaintext
-- 插入数据时的触发器
create trigger tb_user_insert_trigger
    after insert on tb_user for each row
begin
    insert into user_logs(id, operation, operate_time, operate_id, operate_params) values
    (null, 'insert', now(), new.id, concat('插入的数据内容为: id = ', new.id, ' name = ', new.name, ' phone = ', new.phone),
     ' email = ', new.email, ' profession = ', new.profession);
end;

-- 查看触发器指令
show triggers;

-- 插入数据
insert into tb_user(id, name, phone, email, profession, age, gender, status, createtime)
values (25,'Wang','99999999999','wang-nine@gmail.com','计科',19,'1','1',now());
```

运行结果：

此处的 `SHOW TRIGGERS` 用于查看当前数据库中已创建的触发器定义信息，重点核对名称、触发事件、关联表、触发时机与触发语句，而不是查看用户变更日志。目标定义是用户表上的逐行插入后触发器；但上方插入日志语句的拼接括号提前结束，须先修正列值数量不匹配的问题，不能仅凭这段文本认定创建已经成功。

此例的意图是：用户记录成功插入后，逐行触发器读取 `NEW` 中的新行字段，再向日志表写入操作类型、用户主键与描述。上方日志插入语句需要把邮箱、专业也纳入同一个拼接表达式，使值的数量与目标列一致。修正并成功创建后，插入的用户主键为 `25`，日志引用 `NEW.id`；日志自增编号和执行时间则由运行环境决定。

### UPDATE 类型触发器样例

```plaintext
-- 更新数据时的触发器
create trigger tb_user_update_trigger
    after update on tb_user for each row
begin
    insert into user_logs(id, operation, operate_time, operate_id, operate_params) values
    (null, 'update', now(), new.id,
     concat('更新前的数据内容为: id = ', old.id, ' name = ', old.name, ' phone = ', old.phone,' email = ', old.email, ' profession = ', old.profession,
     '更新前的数据内容为: id = ', new.id, ' name = ', new.name, ' phone = ', new.phone,' email = ', new.email, ' profession = ', new.profession));
end;

-- 查看触发器指令
show triggers;

-- 更新数据
update tb_user set age = 99 where id = 25;
```

运行结果：

此处查看触发器时，应核对更新触发器是否关联 `tb_user`、事件是否为更新、时机是否在更新之后，以及是否声明逐行执行。`SHOW TRIGGERS` 展示的是触发器元信息，不会展示某次更新前后的用户数据，也不等同于查询日志表；实际返回哪些定义取决于当前数据库中已成功创建的对象。

此例中，若主键为 `25` 的用户存在且年龄实际发生变化，更新后的 `NEW.age` 为 `99`，更新前的值则来自 `OLD.age`。不过触发器的日志拼接只包含主键、姓名、电话、邮箱和专业，并未记录年龄，所以这次年龄变化不会直接显示在描述字段里；两段文案还都写成了“更新前”，应与 `OLD`、`NEW` 的真实含义区分。

### DELETE 类型触发器样例

```plaintext
-- 删除数据时的触发器
create trigger tb_user_delete_trigger
    after delete on tb_user for each row
begin
    insert into user_logs(id, operation, operate_time, operate_id, operate_params) values
    (null, 'delete', now(), old.id, concat('插入的数据内容为: id = ', old.id, ' name = ', old.name, ' phone = ', old.phone,
     ' email = ', old.email, ' profession = ', old.profession));
end;

-- 查看触发器指令
show triggers;

-- 删除数据
delete from tb_user where id = 25;
```

运行结果：

此处的查看命令用于确认删除触发器的定义：事件为删除，时机在删除之后，并对每个被删除的用户行执行一次。删除场景只能从 `OLD` 读取原行字段，不存在删除后的新行可供 `NEW` 引用。查看定义不会删除用户，也不会直接返回删除操作写入日志表的内容。

此例中，删除语句针对主键为 `25` 的用户；若该行存在并成功删除，触发器就用 `OLD` 保存的原行字段生成删除日志，操作类型取字面量 `delete`。描述字符串虽然写着“插入的数据内容为”，并不改变它属于删除事件这一事实。若目标行不存在便没有相应的逐行触发，不能预设日志条数、自增编号或操作时间。
